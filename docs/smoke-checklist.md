# Android APK 人工 Smoke Checklist（M0-03 任务，2026-08-27）

> **适用范围**：从 GitHub Actions **下载 APK Artifact**（job `assemble` 的 `app-debug`）后，
> 在真机或模拟器上进行的人工验收。
>
> **不**包括：
> - 单元测试覆盖（`./gradlew testDebugUnitTest`）
> - Lint 报告（`./gradlew lintDebug`）
> - 自动化 UI 测试（项目内暂无）
> - 服务端 / 同步 / 共享空间 / 真实电子画册（**未实现**）
>
> **约定**：
> - 每个测试项使用统一格式：前置条件 / 操作步骤 / 预期结果 / 实际结果 / Pass/Fail / 截图或录屏 / GitHub Actions run & Artifact 版本
> - "已知 Demo/占位功能的预期结果"必须**显式记录**当前的合理行为，避免被误判为回归
> - 任何本文件**没有**显式说明"PASS/FAIL 接受"的状态变化，都需要先回文档
> - 本文件**不修改**任何代码、Gradle、Manifest、workflow

## 0. 验收流程概览

```
1. 打开 GitHub Actions 最近一次 main / PR 成功的 run
   https://github.com/<owner>/<repo>/actions/workflows/build.yml
2. 进入 run → 底部 Artifact → 下载 app-debug.zip → 解压得到 app-debug.apk
3. 准备 3 台设备：API 26 / API 29 / API 34（可以是模拟器或真机）
4. 安装：adb install -r app-debug.apk
5. 启动 App：桌面点击 "小确幸" 图标
6. 准备三份环境快照：
   a) 首次启动（清空数据后首次打开）
   b) 空数据（首次启动后立即清空 Room，无任何记录）
   c) 已有数据（首次启动后保留 5 条 Demo 记录）
7. 设置：浅色 / 深色 / 字体 1.0x / 字体 1.3x 各跑一遍
8. 按 §1–§9 顺序执行测试项
9. 把每项的"实际结果 / 截图 / 录屏 / Artifact 版本"填到对应行
10. 在最后 §10 给出整体结论（All Pass / N 项 Fail / 阻塞项清单）
```

| 分享渠道 | 微信/朋友圈/小红书/微博/Copy 按钮无 action | 点击按钮**不响应**（除"保存图片"） | 不崩溃；按钮可见 |
| 时间线卡片点击 | 无记录详情 | 直接进分享页 | 进入的是分享页不是空白页 |
| GP 公式 | 与 PRD 不一致 | 按当前 GPCalculator 公式 | 不崩溃；与公式自洽 |
| 5 条 Demo | 首次启动注入 | 可见 | 可见 |
| 共享空间 | 仅 `Space` 实体与 DAO | 没有任何 UI | 不崩溃；DAO 可用（仅代码可验证） |
| 登录 | 0% | 无入口 | 不出现崩溃/无关页面 |
| 真实画册 | 2024 硬编码 Demo | 翻页可走通 | 翻页无崩溃；显示硬编码内容 |
| `fallbackToDestructiveMigration` | 风险 | 当前使用 | schema 升级场景下数据可能丢失；**M0 阶段不验证** |

### 10.2 硬编码浅色 / 暗色不可读（design-tokens.md §7 同步）

- `HomeScreen.kt`：大量 `Color.Black.copy(alpha=0.04f)` 阴影在暗色模式仍可工作但会显得过重。
- `MusicCard.kt` / `AlbumViewerScreen.kt`：`Color(0xFFF3E5F5)` 等浅色背景在深色模式**不可读**。
- `ProfileScreen.kt`：菜单图标色 `Color(0xFF5E9B6A)` 等是 CSS 主色本身，深色模式可见。
- `AchievementScreen.kt`：`Color(0xFFF5F5F5)` / `Color(0xFFFFF8E1)` 在深色模式**不可读**。
- 视为 PASS 的条件：文字与背景对比度 ≥ 4.5:1（WCAG AA）；不可读的页面对应功能**不阻塞**主流程。
